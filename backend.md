## 3. Mathematical Engine & Formulations

### 3.1 Soul-Weight Valuation Formula

Dead tokens burned in the Altar are evaluated algorithmically to prevent spam dust while awarding logarithmic weight scaling based on burned volume:

$$\text{Weight} = \max\left(1.0, \log_{10}\left(\frac{\text{raw\_amount}}{10^{\text{decimals}}} + 1\right) \times M_{\text{age}}\right)$$

Where:

* $\text{raw\_amount}$: Raw token balance transferred to the Altar contract.
* $\text{decimals}$: Token contract decimals (queried via RPC).
* $M_{\text{age}}$: Liquidity decay multiplier calculated as:

$$M_{\text{age}} = \begin{cases} 1.5 & \text{if token has } 0 \text{ DEX volume for } > 7 \text{ days} \\ 1.0 & \text{otherwise} \end{cases}$$



### 3.2 Pro-Rata Dividend & Karma Allocation

The 30% circular dividend allocation is claimable by stakers and dust-burners based on their epoch Karma score:

$$\text{Share}_i = \frac{\text{Karma}_i}{\sum_{j=1}^{N} \text{Karma}_j} \times \text{Treasury}_{\text{dividends}}$$

Where:

* $\text{Karma}_i$: Total cumulative soul-weight generated by address $i$.
* $\text{Treasury}_{\text{dividends}}$: Total native ETH routed to the dividend contract via the 30% split.

## 4. Smart Contract Specifications

### 4.1 `ThanatosFeeSplitter.sol`

* **Network Target:** Robinhood Chain L2.
* **Role:** Set as the designated creator fee recipient on the Pons launchpad deployer contract.
* **Execution Interface:**
* `receive() external payable`: Intercepts native ETH fee sweeps from Pons.
* Splitting logic:
* **30%** transferred immediately to `devWallet` (liquid founder revenue).
* **40%** transferred to `altarContract` (escrowed for autonomous rebirth liquidity seeding).
* **30%** transferred to `dividendPool` (escrowed for holder/burner claims).





### 4.2 `ThanatosAltar.sol`

* **Role:** Non-custodial graveyard for dead/dust ERC-20 tokens.
* **Key Functions:**
* `sacrificeToken(address tokenAddress, uint256 amount)`: Pulls ERC-20 tokens from user via `transferFrom` into permanent contract lock. Emits indexed event `TokenSacrificed(address indexed user, address indexed tokenAddress, uint256 amount, uint256 timestamp)`.
* `executeRebirthSeed(address factoryAddress, bytes calldata data)`: `onlyAgent` restricted function. Passes accumulated 40% fee ETH directly to the Pons Factory to execute `launchAndBuy`.

## 6. Cloud Functions & Worker Daemons

| Service Name | Trigger Mechanism | Functional Responsibilities |
| --- | --- | --- |
| **`eventIndexer`** | Callable / Log Indexer | • Polls RPC every 5 seconds for `TokenSacrificed` event logs.<br>

<br>• Calculates soul weight via mathematical formulation.<br>

<br>• Executes atomic Firestore batch write to `/sacrifices`, `/leaderboard`, and `/altar_state`. |
| **`epochEvaluationDaemon`** | Cloud Scheduler (`every 1 minutes`) | • Checks if `now() >= death_clock_ends_at` OR `soul_weight_current >= soul_weight_target`.<br>

<br>• Enforces atomic mutex lock (`is_locked = true`).<br>

<br>• Triggers `reincarnationRelayer`. |
| **`reincarnationRelayer`** | Internal Worker | • Aggregates top 3 dead tokens burned during the epoch.<br>

<br>• Calls OpenAI API to generate thematic metadata (e.g., hybrid lore, name, ticker).<br>

<br>• Dispatches `launchAndBuy` transaction to Pons Factory (`0x3711...1A42`).<br>

<br>• Triggers airdrop snapshot. |
| **`airdropWorker`** | Triggered on Rebirth confirmation | • Queries `/leaderboard` sorted by `epoch_karma desc` limit 50.<br>

<br>• Distributes batch transfers of newly minted Phoenix tokens to top sacrificers.<br>

<br>• Resets epoch state: updates target to $\text{Target}_{\text{new}} = \text{Target}_{\text{old}} \times 1.25$, sets new 48-hour clock, and sets `is_locked = false`. |
| **`socialBroadcastEngine`** | Event-Driven (Pub/Sub) | • Tweets burn alerts on sacrifices $> 10\text{ Soul Weight}$.<br>

<br>• Posts countdown warnings at $12\text{h}$, $6\text{h}$, and $1\text{h}$ remaining.<br>

<br>• Publishes official Rebirth announcement with contract address and DexScreener link. |

## 8. Security Controls & Operational Fail-Safes

* **Private Key Isolation:** Agent deployment key is stored in **Google Secret Manager** and accessed strictly via runtime IAM role bindings.
* **Distributed Mutex Lock:** State evaluation workers enforce an atomic lock flag in Firestore prior to initiating blockchain calls to prevent duplicate token minting during network congestion.
* **Slippage & Gas Caps:** The relayer script sets strict maximum base fees and caps the initial seed buy at $0.05\text{ ETH}$ to prevent treasury drainage during gas spikes.
* **Sanitization:** All AI-generated metadata strings are passed through a regex sanitizer to eliminate malformed characters prior to submitting on-chain metadata URIs.
